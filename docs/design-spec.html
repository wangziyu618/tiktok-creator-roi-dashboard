体检结论一：纯佣 ROI 很好看，但它是「假健康」

表面口径 ROI = GMV ÷ 佣金 = 10.99x。但这个 10.99 只把平台佣金算作成本，而纯佣模式的真实成本还有一个大头——免费寄出去的样品。把样品按保守的 $5 / 件（货值 + 头程物流）计入后：

纯佣现金 ROI
10.99x
仅计平台佣金
全成本 ROI（样品 $3/件）
0.31x
佣金 + $1,167 样品
全成本 ROI（样品 $5/件）
0.19x
佣金 + $1,945 样品
设计含义 看板必须双口径呈现 ROI。只报 10.99x 是「数字好看但没用」；只看 0.19x 又会误判模式不成立。真正要管的，是这两条曲线的收敛速度——随着样品投放精度提升，全成本 ROI 逐步向纯佣 ROI 逼近。这条收敛线是整个看板最重要的策略叙事，也是模块一设计一个「双 ROI 对比卡」的原因。

体检结论二：99% 的样品，投给了 0 产出的人

把 1,068 位达人按「漏斗状态 + 产出」切成七层后，资源错配暴露得非常彻底：

样品投放分布（当前快照）389 samples / $375 GMV
A+B 产出层4 件 · 1.0%
C 有内容未转化222 件 · 57.1%
E 寄样未铺货163 件 · 41.9%
F 仅邀约0 件 · 0%

真正带来 GMV 的 8 位达人只吃掉 4 件样品；而 C、E 两层合计 419 人吃掉 385 件（99.0%），产出 $0。这不是 ROI 问题，是投放精度问题。

设计含义 纯佣 BD 的核心资源不是钱，是时间 + 样品。所以模块二的分层不能只按 GMV 排名——那样只有 8 个人有数，其余 99.3% 全是 0，图表会整体空掉。必须按漏斗状态分层，这样每一层都有人、都有明确的下一步动作。这是这套看板区别于通用 GMV 报表的关键设计决策。

01 / DATA FOUNDATION

数据地基：从 ss.xlsx 到可刷新的 Tableau 模型

这一节决定「能不能一键刷新」。四个必须提前解决的结构性问题，不解决的话后面所有图表都做不出来，或者每周要手工返工。

问题清单

问题现状解决方案（必须项）
没有时间字段 23 个字段全是当期快照，ss.xlsx 里看不到任何日期 每次导出后补 snapshot_week（该周周一，用作周 ID）+ snapshot_date。没有这一列，环比 / 趋势 / 周筛选全部无从谈起

D_Intervention 是模块四「策略效果追踪」的专用维表，用来做 Before / After 对照。这张表通常没人做，但它决定了优化动作到底能不能被验证。

落地方案：通配符并集 = 一键刷新

核心机制 不要每次手动改数据源，用 Tableau 通配符并集（Wildcard Union）。把所有周度 CSV 丢进同一个文件夹，统一命名为 YYYYMMDD_creator_weekly.csv。Tableau 连接时用通配符 *_creator_weekly.csv，之后每周只要把新文件丢进文件夹 → 数据源点「刷新」 → 全看板连同所有模块自动更新，零改表、零改公式。

清洗脚本（推荐用它替掉手工加列）

# prepare.py —— 每周跑一次：python prepare.py raw_export.xlsx 2026-10-06
import pandas as pd, sys, datetime as dt

df = pd.read_excel(sys.argv[1], header=0, skiprows=[1])  # 第2行是字段说明，跳过
week_start = pd.Timestamp(sys.argv[2])                       # 该周周一

money = ['Creator-attributed GMV', 'Refunds', 'AOV', 'Est. commission',
         'Creator LIVE-attributed GMV', 'Creator video-attributed GMV', 'Est. flat fee']
pct = ['CTOR', 'CTR']

for c in money:
    df[c] = df[c].astype(str).str.replace(r'[$,]', '', regex=True).replace('', '0').astype(float)
for c in pct:
    df[c] = df[c].astype(str).str.replace('%', '').replace('', '0').astype(float) / 100

# 时间维度——没有这三列，环比 / 趋势全部作废
df['snapshot_date'] = pd.Timestamp(dt.date.today())
df['week_start']    = week_start
df['week_id']       = week_start.strftime('%Y-W%V')

# 样品货值：改成你们真实的单件货值 + 运费
df['sample_cost']    = df['Samples shipped'] * 5.0
df['creator_key']   = df['Creator name'].str.strip().str.lower()

out = f'data/weeks/{week_start.strftime("%Y%m%d")}_creator_weekly.csv'
df.to_csv(out, index=False)
print('written:', out, df.shape)

sample_cost 是全盘最关键的人为设定值——它把「看不见的样品成本」变成可量化分子。建议先和主管对齐单价口径后再定稿。

02 / METRIC DICTIONARY

指标字典与 Tableau 计算字段

所有模块共用同一套计算字段，集中定义一次，避免各图各算一套导致周报里数字打架。以下公式可直接复制进 Tableau 计算字段编辑器。

A. 基础度量

// —— 产出侧 ——
[Net GMV]           = SUM([GMV (num)]) - SUM([Refunds (num)])
[Content Count]     = SUM([Videos]) + SUM([LIVE streams])
[Attributed Orders] = SUM([Attributed orders])

// —— 成本侧（纯佣模式的关键：成本 ≠ 只有佣金）——
[Cash Cost]  = SUM([Commission (num)])
[Total Cost] = SUM([Commission (num)]) + SUM([sample_cost])

// —— 双口径 ROI ——
[ROI (Cash)]      = SUM([GMV (num)]) / NULLIF([Cash Cost],  0)
[ROI (Full Cost)] = SUM([GMV (num)]) / NULLIF([Total Cost], 0)

B. 效率与质量指标

[Commission Rate] = SUM([Commission (num)]) / NULLIF(SUM([GMV (num)]), 0)
[Refund Rate]     = SUM([Refunds (num)])    / NULLIF(SUM([GMV (num)]), 0)
[AOV (Blended)]   = SUM([GMV (num)])        / NULLIF([Attributed Orders], 0)

// 资源效率：纯佣 BD 真正要管的三个"分母"
[GMV per Sample]  = SUM([GMV (num)]) / NULLIF(SUM([Samples shipped]), 0)
[GMV per Content] = SUM([GMV (num)]) / NULLIF([Content Count], 0)
[GPM]             = SUM([GMV (num)]) / NULLIF(SUM([Video views]), 0) * 1000

// 漏斗效率
[Active Creators]  = COUNTD(IF {FIXED [creator_key] : SUM([GMV (num)])} > 0 THEN [creator_key] END)
[Activation Rate]  = [Active Creators] / NULLIF(COUNTD([creator_key]), 0)
[Breakout Rate]    = [Active Creators] / NULLIF(COUNTD(IF SUM([Samples shipped]) > 0 THEN [creator_key] END), 0)

C. 周环比（不受筛选器影响的参数化写法）

为什么不用表计算 「LOOKUP(SUM([GMV]), -1)」写起来最快，但一旦加了周筛选器，表计算就断——筛出单周之后它看不见上一周。要在同一个工作表里同时呈现「本周 / 上周 / 全周期」三组数字，必须用日期参数 + FIXED LOD。 
// Step 1：建参数 [p_Week]，类型 = 日期，可用值来自 [week_start]

// Step 2：三个口径的 GMV（同理可做 Commission / ROI / Active Creators）
[GMV · Selected] = {FIXED : SUM(IF [week_start] = [p_Week] THEN [GMV (num)] END)}
[GMV · Prev Wk]  = {FIXED : SUM(IF [week_start] = DATEADD('week', -1, [p_Week]) THEN [GMV (num)] END)}
[GMV · All Time] = {FIXED : SUM([GMV (num)])}

// Step 3：环比 + KPI 装饰
[WoW GMV %] = ([GMV · Selected] - [GMV · Prev Wk]) / ABS([GMV · Prev Wk])
[KPI Arrow] = IF ISNULL([WoW GMV %])        THEN '—'
             ELSEIF [WoW GMV %] >  0.02 THEN '▲'
             ELSEIF [WoW GMV %] < -0.02 THEN '▼'
             ELSE '▬' END
[KPI Color] = IF [WoW GMV %] >= 0 THEN 'Positive' ELSE 'Negative' END

把 [KPI Color] 拖到「颜色」，再在图例里把 Positive / Negative 分别改成规范里的绿 / 红，即可用一个字段统一控制所有 KPI 卡配色。

LOD 与筛选器的坑 FIXED LOD 在筛选器之前计算。如果看板上有「品类 / BD 负责人」这类筛选器，FIXED 会忽略它们，数字会看起来不对。解决办法：把需要参与总盘计算的筛选器右键 → 添加到上下文（Add to Context）。

D. 达人七层分层（LOD 主字段）

[Creator Tier] =
IF     {FIXED [creator_key] : SUM([GMV (num)])} >= 500 THEN 'S · 头部产出'
ELSEIF {FIXED [creator_key] : SUM([GMV (num)])} >= 100 THEN 'A · 稳定产出'
ELSEIF {FIXED [creator_key] : SUM([GMV (num)])} >   0  THEN 'B · 已破零'
ELSEIF {FIXED [creator_key] : SUM([Videos]) + SUM([LIVE streams])} > 0 THEN 'C · 有内容未转化'
ELSEIF {FIXED [creator_key] : SUM([Products added to showcase])} > 0 THEN 'D · 铺货未产出'
ELSEIF {FIXED [creator_key] : SUM([Samples shipped])} > 0 THEN 'E · 寄样未铺货'
ELSE 'F · 仅邀约·无动作' END
层级判定条件当前人数当前 GMV运营动作
S 头部累计 GMV ≥ $5000—锁库存 + 专属高佣 + 长期合约，防挖角
A 稳定累计 GMV $100–5002$242 · 64.5%加码 SKU、提佣 2–3pt、推动开直播
B 已破零累计 GMV > $06$132 · 35.2%复制其爆款脚本，追加同款 / 组合装
C 有内容未转化发过视频/直播，GMV = 0263$0最高优先级：诊断 CTR / CTOR 哪环断，优化挂车位与口播
D 铺货未产出加了橱窗，未发内容0$0催更 + 发拍摄脚本模板
E 寄样未铺货样品已到，未上架156$0止损区：二次触达，超 3 周无动作停止寄样
F 仅邀约全部为 0641$0批量二次触达，或直接清出池子

03 / MODULE 01

模块一 · 核心指标概览

放在看板最顶部。任务只有一个：让汇报对象 5 秒内知道这周好还是不好，以及钱花在哪。周报截图时，往往只需要这一屏。

设计思路

  1. 双 ROI 并列，主动暴露真实成本。左边「纯佣 ROI 10.99x」，紧挨着右边「全成本 ROI 0.19x」。不加掩饰——这在周报里反而加分，它说明你知道纯佣模式的隐性成本在哪，而不是只挑好看的数字报。
  2. KPI 卡自带环比 + 微趋势。每张卡 = 主数值 + 环比百分比 + 8 周 sparkline。环比用颜色和箭头标注方向，不用让人再去对比两张图。
  3. 成本结构可视化。纯佣不等于零成本。用一条堆叠条把「佣金 vs 样品成本」的绝对金额摆出来，让所有人一眼看到样品才是大头。
  4. 预留目标线。所有 KPI 支持参数目标值（p_Target_GMV / p_Target_ROI），配合子弹图判断达成率。

04 / MODULE 02

模块二 · 达人分层诊断

整套看板的分析重心。任务回答一个 BD 最该回答的问题：这 1,000 多号人里，谁值得我下周继续花时间？

设计思路

  1. 用漏斗状态分层，而不是只用 GMV 排名。当前 99.3% 的达人 GMV 为 0，若只按 GMV 排序，整张图 99% 是空白。按漏斗状态分层（S/A/B/C/D/E/F）后每层都有人、都有明确动作，可视化才有信息量。
  2. 每层给两份占比：产出占比 + 样品消耗占比。把这两个占比并排放，错配就自己跳出来了——这正是当前数据里最触目惊心的那件事。
  3. 散点图找「高投入零产出」。X = 寄样数，Y = GMV，气泡大小 = 曝光。右上角是明星，右下角（高投入零产出）是止损对象，一眼可辨。
  4. 下钻到名单。所有分层图都设为筛选源，点任意一层，右侧明细表立刻出该层达人清单，可直接导出作为本周跟进名单。

核心指标

  • 各层人数分布（Countd creator_key by Tier）
  • 漏斗逐级转化率：邀约 → 寄样 → 铺货 → 出内容 → 拿到曝光 → 破零出单
  • GMV 集中度：Top N 达人 GMV 占比 + 帕累托曲线（当前 Top 10 = 100%）
  • 样品消耗集中度：各层样品占比（当前 C + E 层 = 99.0%）
  • 层级跃迁数：本周有多少人从 F→E、E→D、C→B（跃迁比绝对值更能反映运营有效性）
  • 破零率：破零达人 / 寄样达人（当前 8 / 350 = 2.3%）

05 / MODULE 03

模块三 · ROI 多维度拆解

回答「数字为什么会变」。前面的模块告诉你发生了什么，这个模块告诉你为什么——也是真正体现分析深度、区别于普通数据搬运的地方。

设计思路

  1. 用已验证的乘法链做瀑布归因。既然 GMV = Impressions × CTR × CTOR × AOV 已验证自洽（误差 0.3%），就可以把「本周 GMV 相对上周的变化」精确拆成四个因子的贡献额，做成瀑布图。这是最有含金量的一张图。
  2. 内容形态对比。短视频 vs 直播 vs 商品卡（showcase）三种归因 GMV 各自的体量与效率。源表已提供三个拆分字段，可直接用。
  3. 效率指标 z-score 标准化后同图对比。CTR / CTOR / AOV / GPM 量纲不同，不能直接画在一张图上，标准化后可同一坐标系呈线。
  4. 分层 × 周热力图。找「哪一层在哪个周有过跃迁」，给复盘提供时间切片。

06 / MODULE 04

模块四 · 优化策略与效果追踪

把分析变成动作，并验证动作有没有用。这是最能体现策略思维的一环——前三个模块是「看懂」，这一模块是「做成」。

设计思路

  1. 输出四张可执行名单。不输出花哨图表，输出「下周该联系谁」的清单。每张名单配人数、预计影响 GMV、预计节省样品数，让看板直接驱动动作。
  2. 干预前 / 后对照（Before-After Cohort）。这才是「效果追踪」的本质。以 D_Intervention 里记录的 intervention_week 为分界，对比干预前 2 周 vs 后 2 周的同组达人 GMV / 激活率变化。没有对照组，任何优化效果都是自说自话。
  3. 目标达成追踪用子弹图。实际 vs 目标（参数化），每人 / 每层一条。
  4. 用动态文本自动生成周报结论。把 [Weekly Headline] 放在模块顶部文本框，每周自动更新。这是节省时间最实在的一处。
